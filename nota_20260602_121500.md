# Refatoração Visual: Inversão de Topologia do Diagrama de Arquitetura

**Implementação**
- Alteração da diretiva estrutural do arquivo Mermaid `diagrama_de_arquitetura.mmd`, mudando a orientação do grafo de `TD` (Top-Down) para `BT` (Bottom-Top).

**Motivo**
- Atender ao requisito de inverter a disposição do diagrama, posicionando a interface com o usuário (Camada de View / Thymeleaf) na parte superior e a infraestrutura de dados (Banco de Dados Relacional) na base, sem que fosse necessário reescrever a lógica das conexões e setas de fluxo de dados (ResultSet -> View).

**Benefício**
- Essa orientação (View no topo, Infraestrutura na base) reflete o padrão mental clássico da indústria para arquiteturas em camadas (N-Tier e Clean Architecture). Torna a leitura mais intuitiva para novos desenvolvedores, que geralmente visualizam a interação do usuário acontecendo "na superfície" e as consultas ao banco de dados ocorrendo "nas profundezas" do sistema.

## Questão
Excelente! Eu gostaria de um ajuste que seria "inverter" o diagrama, onde o Banco de Dados Relacional fica embaixo do diagrama e a Camada d View fica em cima.

## Resposta Completa do Assistente
Para inverter a disposição visual do diagrama — colocando a **View no topo** e o **Banco de Dados na base** — a forma mais elegante no Mermaid é alterar a diretiva de direção do grafo de `TD` (Top-Down, ou seja, de cima para baixo) para `BT` (Bottom-Top, de baixo para cima). 

Dessa forma, o Mermaid desenha o primeiro nó (Banco de Dados) na parte inferior e vai subindo as setas até a Camada de View no topo, mantendo perfeitamente o fluxo de dados que já mapeamos. É uma representação clássica em arquiteturas N-Tier (onde o cliente fica em cima e a infraestrutura embaixo).
