# Planejamento: Refatoração do Fluxo de Checkout

**Implementação**: Planejamento estratégico para a refatoração do fluxo de finalização de compras (Checkout). A estratégia abrangerá a atualização dos templates Twig para alinhamento com as regras de *Scoped CSS* (`egen-`), criação da lógica assíncrona (AJAX Multi-step) no Front-end, e adequação dos Controllers PHP para consumo via API (JSON).

**Motivo**: Como os componentes de Login e Carrinho foram modernizados para fluxos sem recarregamento (Single Page Interactions), o Checkout tradicional síncrono tornou-se um gargalo de performance e Experiência do Usuário (UX). O arquivo de estilos (`new-stylesheet.css`) já contém as fundações visuais para uma experiência *Premium* em etapas.

**Benefício**: O Checkout Multi-passos assíncrono reduz drasticamente a fricção de compra, ocultando a complexidade de formulários extensos através da divisão em blocos (Identidade, Entrega e Pagamento). Isso acelera o processamento de regras de negócios parciais (como cotação de frete) e aumenta diretamente a Taxa de Conversão da loja.

## Resposta Completa do Assistente
Excelente decisão! O fluxo de Checkout (Finalização de Compra) é o coração de qualquer e-commerce. Agora que o Carrinho e o Login já operam de forma fluída e assíncrona (como uma Single Page Application), levar essa mesma experiência para o Checkout garantirá uma redução drástica na taxa de abandono de carrinho.

Analisando o seu arquivo `new-stylesheet.css`, notei que a equipe de design já deixou toda a **Identidade Visual Premium** preparada para um **Checkout Multi-passos (Multi-step)**. Já temos classes excelentes como `.egen-checkout-page`, indicadores de progresso (`.egen-checkout-progress__step`), e transições suaves entre as etapas (`.egen-checkout-step.active`).

Para estruturarmos o Checkout na Alpha Engine, proponho o seguinte plano de ataque em três frentes:

1. **Camada de Visão (Twig)**: Vamos precisar revisar o arquivo base do checkout (provavelmente `checkout.html.twig` ou similar) para garantir que ele esteja amarrado com as classes `.egen-` protetivas do novo CSS e dividido nas etapas corretas (ex: Identificação, Endereço, Frete, Pagamento).
2. **Camada de Interação (`app.js` ou `checkout.js`)**: Precisaremos criar a lógica de navegação entre as etapas (`Next` / `Prev`) interceptando os formulários de cada passo via AJAX. Por exemplo: ao preencher o CEP, chamamos o backend via `fetch()`, calculamos o frete e já liberamos o passo de Pagamento sem recarregar a tela (usando as notificações flutuantes em caso de erro).
3. **Camada de Dados (PHP Controllers)**: Adaptar os endpoints do Checkout para receberem os pacotes de dados de cada etapa e retornarem um JSON de validação (assim como fizemos com o Login).
