# Otimização: Cache-Aside na Busca e Listagem de Produtos

**Implementação**
Aplicação do padrão *Cache-Aside* no método `getSearchData` do `ProductRepository`. Foi gerada uma chave de cache dinâmica baseada em um hash MD5 (`json_encode`) dos parâmetros de filtro de busca (com chaves previamente ordenadas), combinados com os IDs de idioma, loja e grupo de cliente.

**Motivo**
O método `getSearchData` não apenas formata os dados para o *Skinny Controller*, mas orquestra a chamada de categorias, dados brutos de produtos e o cálculo total de paginação de forma pesada. Em eventos de alto tráfego (como campanhas ou listagens padrão nas *Home Pages*), a repetição de queries com filtros idênticos sobrecarregava a camada de banco de dados.

**Benefício**
Consultas e listagens idênticas retornam em O(1) de forma instantânea na memória. O processamento de orquestração de paginação e filtragem também é suprimido na camada da aplicação, acelerando o tempo de resposta substancialmente. O tempo de vida (TTL) de 5 minutos assegura que flutuações voláteis de estoque e preços sejam validadas a curto prazo sem comprometer a integridade dos dados, mitigando picos severos de acesso.

## Questão
Podemos aplicar o mesmo padrão de cache **ProductRepository.php** o método getSearchData` para listagens e buscas comuns?

## Resposta Completa do Assistente
Com toda certeza! É o passo perfeito para complementar as otimizações feitas na vitrine de produtos.

O método `getSearchData` é muito estratégico porque ele alimenta a busca, as páginas de categorias e todos os componentes de listagem. Como esses resultados variam dependendo dos filtros (ex: número da página, termo pesquisado, limite), precisamos gerar uma **chave de cache inteligente** usando um hash (`md5`) do array de parâmetros junto com o idioma, loja e grupo do cliente. 

Adicionei um passo importante na implementação: antes de gerarmos o hash, ordenamos as chaves do array de filtros (`ksort`), assim evitamos duplicação de cache caso a URL passe os parâmetros em ordens diferentes (ex: `?page=1&limit=10` vs `?limit=10&page=1`). O TTL (Tempo de Vida) será definido como 5 minutos (300 segundos) para garantir respostas instantâneas sem deixar o estoque e preços defasados.
