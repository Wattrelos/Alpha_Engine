# Refatoração: Validação Algorítmica de CPF (Módulo 11) no Backend

**Implementação**: Injeção de rotina de validação matemática de CPF baseada no cálculo de Módulo 11 (dígitos verificadores) diretamente no método `save()` do controlador `catalog/controller/account/edit.php`. O código efetua a limpeza de formatação e previne sequências viciadas (ex: 111.111.111-11).

**Motivo**: A validação anterior de CPF estava restrita à camada de Front-end (via `verifica-formulario-cadastro-cliente.js`). Como scripts client-side são bypassáveis, a aplicação estava exposta a receber dados inconsistentes ou lixo via requisições POST adulteradas.

**Benefício**: Segurança cibernética e integridade de CRM. Garante-se que todos os cadastros de "Pessoa Física" ('F') que trafegarem na API de edição de conta contenham CPFs matematicamente válidos. O Controller fará a checagem usando _Type Casting_ estrito para prevenir exceções no PHP 8 e enviará o alerta diretamente para a view (via array JSON de erros).

## Resposta Completa do Assistente
É uma excelente observação! O arquivo JavaScript `verifica-formulario-cadastro-cliente.js` que você mostrou faz um ótimo trabalho de UX (User Experience) validando o Módulo 11 em tempo real no navegador do cliente. 

No entanto, **validação em JavaScript pode ser facilmente burlada** por um usuário mal-intencionado (desabilitando o JS ou forjando uma requisição POST direta via Postman/cURL). Para garantir a integridade dos dados no banco, a mesma lógica matemática precisa existir no backend (PHP).

Como você pediu para injetarmos isso diretamente no método `save()` do seu `edit.php`, vamos capturar o campo `cpf_cnpj`, verificar se a pessoa é do tipo `F` (Física) e, então, aplicar o algoritmo do Módulo 11.
