# Otimização: Eliminação de N+1 Queries no WishlistRepository

**Implementação**
Refatoração do método `getWishlist` para utilizar o padrão *Eager Loading*. As múltiplas chamadas a `productRepository->getProduct()` dentro do loop foram substituídas por uma única chamada a `productRepository->getProducts()` que busca todos os produtos da lista de desejos de uma só vez. Adicionalmente, as múltiplas queries de `DELETE` para produtos inválidos foram consolidadas em uma única chamada de exclusão em massa (`deleteWishlistProducts`).

**Motivo**
A implementação anterior causava um problema de N+1 queries, disparando uma consulta `SELECT` para cada item na lista de desejos do cliente. Em casos de produtos inválidos, também disparava uma consulta `DELETE` para cada um, resultando em `1 + N (selects) + M (deletes)` queries, o que degrada severamente a performance em listas de desejos com muitos itens.

**Benefício**
Redução drástica do número de queries ao banco de dados, de O(N) para O(1) para leitura e O(1) para escrita de remoção. Isso acelera o carregamento da página da lista de desejos, diminui a carga no servidor de banco de dados e melhora a escalabilidade da funcionalidade. A otimização também se beneficia do cache já existente no método `ProductRepository->getProducts`.

## Questão
O método `getWishlist` faz uma query para cada produto dentro de um loop. Podemos otimizar isso para evitar o problema de N+1?

## Resposta Completa do Assistente
Sua observação foi perfeita! Você identificou um dos gargalos de performance mais clássicos e impactantes: o **problema de N+1 queries**.

No método `getWishlist`, o código primeiro faz 1 query para buscar os IDs dos produtos na lista de desejos e depois, dentro de um loop, executa +N queries (uma para cada produto) para buscar os detalhes de cada um. Se um cliente tiver 20 itens, isso resulta em 21 queries ao banco de dados. Pior: se um produto se torna inválido, ele dispara outra query para deletá-lo, também dentro do loop.

Para resolver isso, apliquei o padrão **Eager Loading** (Carregamento Ansioso), que elimina completamente o problema de N+1 tanto na leitura quanto na escrita. Essa refatoração transforma o custo da operação de O(N) para O(1), resultando em um ganho de performance massivo. Para a remoção em massa, assumi a criação de um novo método `deleteWishlistProducts` no `WishlistMapper`, que executaria uma query `DELETE ... WHERE product_id IN (...)`, uma prática padrão para este tipo de otimização.
