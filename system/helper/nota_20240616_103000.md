# Segurança: Sanitização Anti-XSS para Campos Dinâmicos (EntityMapper)

**Implementação**: Recomendação de criação de um método `sanitizeInput(mixed $data)` recursivo no `EntityMapper` que utiliza `htmlspecialchars($data, ENT_QUOTES | ENT_HTML5, 'UTF-8')` para varrer e limpar arrays recebidos de requisições POST/GET.

**Motivo**: A proteção nativa do PDO cobre apenas a camada de persistência (SQL Injection). Quando a entidade aceita arrays diretamente (como o `setCustomField` modificado recentemente) e faz o `json_encode()`, as tags HTML/JS maliciosas são guardadas "cruas" no banco. Ao renderizar esses campos no painel de controle ou na loja sem os filtros do Twig, o navegador executa o payload, configurando uma vulnerabilidade clássica de Reflected/Stored XSS.

**Benefício**: Limpar a entrada de dados diretamente no `EntityMapper` atua como um poderoso "Gateway de Sanitização". Isso garante que todas as entidades hidratadas da Alpha Engine só receberão strings limpas e seguras, isentando o desenvolvedor de lembrar de usar filtros de escape toda vez que for imprimir dados complexos na camada de View (Frontend ou Admin).

## Resposta Completa do Assistente
Sim, sua preocupação é extremamente válida e demonstra uma ótima visão de segurança (Security by Design)!

Embora a nova arquitetura da Alpha Engine com PDO e `DataAccessObject` utilize Prepared Statements (que nos **protegem 100% contra SQL Injection**), ela **não previne o XSS (Cross-Site Scripting)**. 

Se um usuário mal-intencionado preencher um campo personalizado de texto no frontend com `<script>alert('Fui hackeado!');</script>`, esse dado será convertido para JSON e salvo com segurança no banco. Porém, quando um administrador for visualizar o pedido no painel do OpenCart (que frequentemente renderiza Custom Fields de forma crua), o script será executado no navegador dele, podendo roubar a sessão administrativa.

Como o arquivo `EntityMapper.php` não está em nosso contexto atual para eu modificá-lo diretamente, recomendo fortemente que você adicione uma função de sanitização recursiva nele, interceptando os dados antes que eles cheguem à entidade `Customer`.
