# Evolução Arquitetural: Inserção de Cache Distribuído (Redis)

**Implementação**
- Inserção de um nó de Cache Distribuído (`Redis`) no arquivo `diagrama_de_arquitetura.mmd`.
- Modificação do fluxo de dados visual, posicionando o Redis estrategicamente entre a saída do `Hydrator` (Entidades e DTOs) e a camada do `Repository`.
- Mapeamento de setas condicionais representando situações de *Cache Hit* (retorno direto em memória) e *Cache Miss* (necessidade de passagem primária pelo banco de dados).

**Motivo**
- Representar visualmente a técnica de mitigação de sobrecarga de leitura e redução do problema de N+1 Queries. Em arquiteturas baseadas em Java ou PHP, a hidratação por Reflection é custosa; aplicar o cache diretamente nos objetos/DTOs hidratados antes que cheguem ao Repositório economiza ciclos de processamento da linguagem e consultas (I/O) de banco de dados.

**Benefício**
- O diagrama agora reflete um ambiente corporativo de alta escalabilidade. Esta topologia de cache diminui radicalmente o tempo de resposta (TTFB) para a camada de visualização (Thymeleaf/Twig) em dados de leitura pesada (Read Models), mantendo o ecossistema robusto.
