# Refatoração: Adaptação do Controller de Login para Respostas AJAX (JSON)

**Implementação**: Orientação técnica e estruturação do Controller de Login (PHP) para suportar requisições híbridas. A lógica consiste em validar o cabeçalho `$_SERVER['HTTP_X_REQUESTED_WITH']` e, quando for identificado como `xmlhttprequest`, interromper o ciclo normal de renderização/redirecionamento da Alpha Engine, enviando cabeçalhos `Content-Type: application/json` e códigos de status HTTP apropriados (200 para sucesso e 400/401 para falha).

**Motivo**: Para que a injeção assíncrona recentemente criada no `app.js` funcione corretamente, o backend precisa responder em uma linguagem compreensível (JSON) e respeitar a especificação HTTP (alterando o Status Code). Devolver um HTML completo da página dentro do AJAX quebraria o fluxo do Front-end.

**Benefício**: O ecossistema se torna completamente desacoplado na camada de interação. O Backend serve os dados puros (Data-Driven), deixando ao Front-end (Client-Side) a total responsabilidade de notificar o usuário (usando os *Toasts*) e controlar as rotas de redirecionamento dinamicamente, blindando o aplicativo contra perdas de contexto na UI e mantendo compatibilidade retroativa para navegadores sem JS.

### Pontos cruciais na adaptação do Controller:
1. **O Código HTTP (`http_response_code`)**: Repare que na falha, eu coloquei um `http_response_code(401);`. Se você deixar como 200 (OK), o nosso `fetch()` vai achar que deu tudo certo e mostrará um balão verde. O status de erro é o gatilho para o balão vermelho.
2. **O `exit;` após o JSON**: Isso previne que qualquer outro lixo ou HTML gerado pelo framework polua a resposta, quebrando o `response.json()` no lado do JavaScript.
