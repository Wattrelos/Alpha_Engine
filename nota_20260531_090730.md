# [Resolução Dinâmica de Rotas de Autenticação]

**Implementação**:
Refatoração de `RegisterAction.php` e `LoginAction.php` para utilizar a classe `RouteContext` do Slim 4 e recuperar a instância de `RouteParser`. Isso permite gerar dinamicamente as URLs de login e do painel do cliente (`account.index`), respeitando o idioma ativo na requisição (`lang`).

**Motivo**:
Anteriormente, o redirecionamento pós-cadastro era direcionado para uma string fixa (`/login?success=1`), ignorando o idioma do usuário. No login, caso não houvesse redirecionamento explícito, o usuário era direcionado de forma genérica para a raiz `/`.

**Benefício**:
Assegura que o fluxo de navegação respeite as rotas internacionalizadas dinamicamente, enviando o usuário para a versão correspondente no seu idioma (ex: `/pt-br/login` ou `/pt-br/account`).

## Questão
Agora, vamos usar as configurações de rotas para hidratar as variáveis Twig dinamicamente? Que tal começarmos por core/Controller/Actions/Customer/Auth/RegisterAction.php e core/Controller/Actions/Customer/Auth/LoginAction.php ?

## Resposta Completa do Assistente
Implementamos a resolução dinâmica de rotas em `RegisterAction.php` e `LoginAction.php` usando `RouteContext::fromRequest($request)->getRouteParser()` do Slim 4.

- Em `RegisterAction.php`, a URL de sucesso no cadastro redireciona para a rota nomeada `'login.form'` com o parâmetro de idioma corrente (ex: `/pt-br/login?success=1`).
- Em `LoginAction.php`, o redirecionamento padrão (caso nenhum redirecionamento específico seja passado via POST) agora aponta dinamicamente para o painel do cliente (`'account.index'`, ex: `/pt-br/account`).
