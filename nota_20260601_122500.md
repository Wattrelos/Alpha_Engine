# Correção de Transição de Status e Confirmação de Pedidos no Checkout

**Implementação**
- Atualização do método `addHistory` no `OrderMapper.php` para executar um comando `UPDATE` que atualiza a coluna `order_status_id` na tabela `order`, sincronizando-a com a tabela `order_history`.
- Ajuste no processador final do checkout `SubmitCheckoutAction.php` para invocar o método `$orderRepository->confirm()` imediatamente após a inserção bem-sucedida do pedido no banco de dados. Isso transiciona a situação do pedido do estado preliminar (`0`) para o status padrão configurado no sistema (geralmente `1` - Pendente).
- Execução de script corretivo direto no banco de dados para alterar o `order_status_id` dos 4 pedidos de teste anteriores de `0` para `1`, permitindo que apareçam na tela do cliente.

**Motivo**
- Pedidos recém-criados permaneciam com o status `0` ("não confirmados") porque o método `confirm()` não era executado na rota final do checkout. Adicionalmente, a lógica interna do `addHistory` inseria o histórico de transição, mas esquecia de atualizar o status atual na tabela principal de pedidos (`tbkk_order`), fazendo com que as listagens de histórico de pedidos no painel do usuário ficassem em branco (visto que elas filtram por `order_status_id > 0`).

**Benefício**
- Correção de bug crítico no fluxo de vendas: agora os pedidos criados passam a ter o status inicial correto de forma consistente.
- Correção de bug visual na área do cliente: os pedidos e seu histórico agora são mostrados corretamente em "Meus Pedidos" e "Histórico de Pedidos".

## Resposta Completa do Assistente
Localizei e corrigi a falha estrutural que causava o comportamento:

1. **Ausência de Confirmação no Checkout (`SubmitCheckoutAction.php`)**:
   - O checkout criava o pedido via DTO, mas o fluxo final redirecionava para a página de sucesso sem chamar o método `confirm` do repositório. Por isso, os pedidos ficavam com `order_status_id = 0`.
   - Adicionamos a chamada `$orderRepository->confirm($orderId, $defaultOrderStatusId, ...)` usando a configuração padrão do sistema (geralmente `1` - Pendente) após a criação do pedido.

2. **Falta de Atualização na Tabela Principal (`OrderMapper.php`)**:
   - Descobrimos que o método `addHistory()` do `OrderMapper` inseria corretamente o registro de histórico, mas não realizava o `UPDATE` correspondente da coluna `order_status_id` na tabela principal `order`.
   - Atualizamos a função `addHistory()` para atualizar a tabela principal de pedidos sincronizadamente.

3. **Correção Direta**:
   - Executamos uma query corretiva no banco de dados para alterar o status dos 4 pedidos existentes do cliente `16686` para `1` para que eles sejam imediatamente exibidos em "Meus Pedidos".
