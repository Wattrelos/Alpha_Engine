# Correção de Bug: A void method must not return a value (ProxyFactory)

**Implementação**: Adicionada verificação para o tipo de retorno dos métodos durante o processo de reflection da entidade original. Se o método apresentar o retorno como `void` (ou `never`), a instrução `return parent::...` no código gerado dinamicamente é substituída por apenas `parent::...`.

**Motivo**: A partir do PHP 7.1+, métodos com assinatura de retorno `void` não aceitam que a instrução `return` venha acompanhada de uma expressão de valor. Ao gerar o código da classe proxy, injetar condicionalmente ou incondicionalmente um `return parent::metodo();` num escopo `void` causa um Erro Fatal em tempo de compilação durante o `eval()`.

**Benefício**: Restaura a estabilidade da aplicação, garantindo que o `ProxyFactory` possa envolver (wrap) e interceptar corretamente qualquer método que porventura possua o retorno `void` - comum em setters, rotinas de confirmação de pedido e deleção em repositórios - eliminando de forma definitiva possíveis WSODs (White Screen of Death).

## Resposta Completa do Assistente
Esse erro acontece porque a partir do PHP 7.1, métodos que possuem a declaração de tipo de retorno `void` não podem retornar nenhum valor. Na sua classe `ProxyFactory`, o código que está sendo gerado via `eval()` para os métodos fantasma usa sempre a instrução `return parent::{$methodName}(...)`. Assim, quando o proxy tenta sobrescrever um método original que retorna `void` (como por exemplo `getTotal()` no `total/coupon.php`), o PHP entende que você está tentando retornar o resultado da chamada pai, resultando nesse erro fatal de compilação.

Para corrigir isso, precisamos identificar dinamicamente durante o processo de *reflection* se o método possui retorno `void` (ou `never`) e, caso tenha, simplesmente chamar a implementação pai sem usar o prefixo `return`.

(As correções foram aplicadas diretamente na classe `/var/www/html/agsonhos/core/Model/DataAccessObject/ProxyFactory.php` utilizando um operador ternário para formatar a string de resposta com ou sem o `return`).
