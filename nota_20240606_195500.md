# Refatoração: Separação de Preocupações no payment_method.twig

**Implementação**: Extração completa de blocos HTML `<style>` e `<script>` inseridos inline (inline-scoping) no sub-componente `payment_method.twig`. O CSS foi migrado nativamente para a folha base `new-stylesheet.css` e o script de iteração (listeners para cartões de rádio-button) foi alocado sob a rotina de inicialização global do fluxo no `checkout.js`. A classe utilitária residual `mt-4` (Bootstrap) foi convertida na classe semântica `.egen-payment-note-group`.

**Motivo**: Manter código CSS e JavaScript embutido em visões Twig secundárias viola gravemente o princípio de Separation of Concerns (SoC). Isso degrada a performance de navegação, prejudica a compilação e cache (minificação de assets) e impede o reaproveitamento de código em outras instâncias do projeto.

**Benefício**: Centralização do *Behavior* (JS) e *Appearance* (CSS). Além de garantir a adequação 100% à convenção Scoped (`egen-`), o DOM gerado fica leve e os navegadores conseguem efetuar o cache otimizado e assíncrono dos recursos via arquivos externos estáticos, pavimentando um fluxo de Checkout mais veloz e imune a renderizações bloqueantes (Render-Blocking Resources).

Porém, encontrei **dois grandes pontos de refatoração arquitetural** fundamentais para manter a consistência da Alpha Engine:
1. **Classe Utilitária do Bootstrap**: O grupo do campo de texto de observações ainda possuía um resquício do Bootstrap (`mt-4`). Substituiremos por uma classe semântica nossa (`.egen-payment-note-group`).
2. **Quebra de Separação de Preocupações (Separation of Concerns)**: O template possuía tags `<style>` e `<script>` injetadas direto no HTML (inline). Numa arquitetura de front-end limpa, todo o CSS deve ir para a nossa folha de estilos (`new-stylesheet.css`) e o controle do DOM deve ir para o nosso controlador JavaScript (`checkout.js`).
