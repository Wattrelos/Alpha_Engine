# Correção: Exibição de Aviso de Login Incorreto no Frontend

**Implementação**: Alteração da estrutura do payload JSON de erro na classe `LoginAction` (Customer). O valor da propriedade `error` foi alterado de uma string pura para um array associativo contendo a chave `warning`.

**Motivo**: Os handlers de formulário assíncronos (AJAX) em sistemas baseados em ecossistemas como o do OpenCart esperam um formato de objeto estrito para renderização de erros. Ao receber uma string diretamente em resposta a um status 400 (Bad Request), o interpretador JavaScript falha ao buscar a propriedade interna (ex: `json.error.warning`), resultando na ausência do alerta visual na interface.

**Benefício**: Restaura o feedback visual de erro para o usuário final, padronizando a comunicação da API do login de clientes com o formato correto esperado pelo client-side, mantendo consistência com o restante das rotas do sistema.

## Resposta Completa do Assistente
Bom dia! O problema que você está enfrentando ocorre devido à estrutura dos dados JSON que a sua Action retorna quando a validação falha.
Nos sistemas frontend inspirados ou migrados do OpenCart (que utilizam atributos como `data-oc-toggle="ajax"`), o JavaScript padrão espera que as mensagens de erro globais venham dentro de uma propriedade chamada `warning` no objeto de erro (ou seja, `json.error.warning`).
Atualmente, o seu `LoginAction.php` do cliente retorna o `error` como uma **string direta**. Quando o script de AJAX no frontend (que recebe o HTTP 400) tenta ler a propriedade `warning` dessa string, ele recebe `undefined` e acaba falhando silenciosamente, sem injetar o alerta na tela.
Para resolver, basta transformar a sua string de erro em um array associativo com a chave `warning`. Dessa forma, mantemos o status `400 Bad Request` que o seu painel já utiliza, mas o payload é entregue num formato que o seu JavaScript consegue renderizar.
