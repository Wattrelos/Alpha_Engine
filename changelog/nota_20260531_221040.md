# [Generalização e Especialização do Fluxo de Autenticação na Alpha Engine]

**Implementação**
Desenvolvimento de uma arquitetura orientada a objetos para o fluxo de autenticação e sessões da Alpha Engine. Criamos a interface `AuthServiceInterface`, a classe base abstrata `AbstractAuthService` e as especializações concretas `CustomerAuthService` (para clientes) e `AdminAuthService` (para administradores). Removemos a classe legada `AuthService` e adaptamos os controladores e o contêiner de injeção de dependências (`AppContainer`) no bootstrap para registrar e resolver os novos serviços automaticamente.

**Motivo**
A Alpha Engine precisava de uma separação de escopos clara entre clientes e administradores. O painel administrativo usava credenciais hardcoded estáticas e havia sobreposição no cookie `session_id`. A generalização permite compartilhar a lógica complexa de persistência no Redis (ou fallback em `$_SESSION`) enquanto isola chaves, cookies, e o repositório de dados de cada tipo de usuário.

**Benefício**
- **Arquitetura Escalável:** Criação de novos escopos de login facilitada pelo modelo abstrato comum.
- **Segurança de Sessão:** Isolamento completo de cookies (`session_id` vs `admin_session_id`) e prefixos no Redis (`sessao:` vs `sessao:admin:`).
- **Fim das Credenciais Hardcoded:** Autenticação administrativa agora dinâmica e baseada em hashes de senha seguros via `UserRepository`.

## Questão
Primeira etapa: Vamos criar uma generalização e, a partir dela, derivar serviços específicos ou especializações. Criar uma classe abstrata  e/ou uma interface, com a lógica comum de autenticação (como checagem de hash de senha, geração de tokens e expiração) e depois criar duas classes filhas focadas no escopo de cada tipo de usuário. O que acha? Tens autonomia para decidir o que for melhor.
