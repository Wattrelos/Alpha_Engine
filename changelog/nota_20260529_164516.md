# [Failsafe de Redis e Estabilização de Logout na Alpha Engine]

**Implementação**:
1. **Resiliência do Redis no AuthService**: O `AuthService.php` (`core/Auth/Services/AuthService.php`) foi atualizado para capturar qualquer exceção de conexão (`Predis\Connection\Resource\Exception\StreamInitException` ou similar) no construtor. Foi definido um timeout de conexão baixo (1.0s) para evitar lentidão e, caso a conexão falhe, a flag `$this->useRedis` é definida como `false`. As operações de persistência e expiração de sessão passam a usar de forma transparente a sessão nativa do PHP (`$_SESSION`).
2. **Resiliência do Redis no SessionMiddleware**: A mesma lógica de captura de exceção foi adicionada ao `SessionMiddleware.php` (`core/Auth/Middleware/SessionMiddleware.php`). Caso o Redis esteja inoperante, o middleware lê o cookie `session_id` e busca os dados de sessão decodificados a partir do `$_SESSION`, além de gerenciar a expiração local de forma automática.
3. **Ação de Logout Decoupled**: Foi implementada a classe `LogoutAction.php` (`core/Controller/Actions/Customer/Auth/LogoutAction.php`) herdando corretamente de `ActionInterface`. A limpeza do cookie de sessão foi migrada de um `header()` bruto para o cabeçalho PSR-7 `Set-Cookie` via `$response->withHeader('Set-Cookie', ...)`, garantindo o redirecionamento com HTTP 302 para a rota `/login`.
4. **Mapeamento de Rotas e Binds**: O arquivo de boot `public_html/index.php` foi modificado para importar `LogoutAction`, registrando a rota `GET /logout`.
5. **Autoload Clean-up**: O arquivo duplicado obsoleto `core/Services/Auth/AuthService.php` foi removido e o autoloader foi regenerado via `composer dump-autoload -o`.

**Motivo**:
A infraestrutura local de desenvolvimento muitas vezes não possui o Redis ativo ou instalado, o que disparava erros fatais de conexão impedindo a execução básica da aplicação. O fallback automático (failsafe) garante a resiliência do sistema em qualquer ambiente. Além disso, o fluxo de encerramento de sessão (Logout) precisava de finalização para garantir a segurança da autenticação de ponta a ponta na Alpha Engine.

**Benefício**:
- **Ambiente de Dev Simplificado**: Desenvolvedores não precisam subir servidores Redis adicionais em desenvolvimento, pois a aplicação faz o fallback transparente e automático para sessões locais do PHP.
- **Portabilidade**: Flexibilidade para rodar em produção de alta concorrência com Redis e em servidores simplificados de homologação/desenvolvimento via sessões clássicas.
- **Estabilidade do Fluxo de Usuário**: O logout remove de forma segura e limpa as credenciais do cliente, tanto no storage (Redis/$_SESSION) quanto no navegador do cliente (expirando o cookie).

## Resposta Completa do Assistente
Para solucionar o erro fatal de conexão recusada com o Redis em ambientes que não possuem o serviço instalado ou rodando e, ao mesmo tempo, concluir a funcionalidade de Logout, realizamos as seguintes ações no ecossistema da **Alpha Engine**:

1. **Implementação de Failsafe de Redis**:
   - Atualizamos o `AuthService` e o `SessionMiddleware` para tratar exceções ao inicializar o `Predis\Client`.
   - Adicionamos um timeout agressivo de 1.0s para conexões com o Redis, evitando lentidões na requisição inicial caso o Redis esteja off.
   - Caso a conexão falhe, o sistema ativa uma flag interna de fallback e passa a salvar/recuperar as informações da sessão do usuário utilizando as sessões nativas do PHP (`$_SESSION`), mantendo a criptografia e consistência de dados do cliente sem quebrar a execução do site.

2. **Estabilização da Ação de Logout**:
   - Corrigimos o script `LogoutAction.php` adicionando o import de `ActionInterface` para resolver erros de tipagem.
   - Substituímos a chamada direta de `header()` para manipulação do cabeçalho de resposta do Slim (`$response->withHeader('Set-Cookie', ...)`).
   - O logout agora limpa as sessões ativas (seja no Redis ou em `$_SESSION`) e expira o cookie `session_id` de forma limpa.

3. **Mapeamento da Rota `/logout`**:
   - Importamos e associamos a rota `GET /logout` diretamente ao container de dependências Slim (`public_html/index.php`).

4. **Saneamento e Limpeza**:
   - Excluímos a classe duplicada `/core/Services/Auth/AuthService.php` para evitar incompatibilidade no autoloader PSR-4.
   - Regeneramos as classes com `composer dump-autoload -o`.
