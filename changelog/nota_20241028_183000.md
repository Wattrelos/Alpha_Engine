# Refatoração: Purificação de Domínio do ProductRepository

**Implementação**: 
Abolição completa de todos os métodos acoplados à view dentro do `ProductRepository` (`getProductDisplayData`, `getSearchData`, `getProductThumbData`). No lugar deles, foi implementado o `getFullProduct()`, focado em Batch Loading e agindo como uma fonte unificada (Aggregate Root) que devolve as entidades relacionadas (opções, descontos, imagens) em seu estado bruto. Adicionalmente, `CategoryRepository` foi ajustado para parar de consumir a formatação de Thumbnails e passar a delegar produtos puros para a sua Action/View.

**Motivo**: 
A classe misturava responsabilidades gravíssimas: além de atuar no banco de dados, ela possuía regras exclusivas do Controller e da View, como cálculo visual de impostos, formatação global de moedas, manipulação e resize de URLs de imagens (`ImagePresenter`) e carregamento de dicionários literais (`loadLanguage()`).

**Benefício**: 
Respeito incondicional à arquitetura Clean e Domain-Driven. O Repositório volta a ser uma interface estrita de dados que pode ser facilmente reaproveitada por APIs JSON e CLI. Todo o overhead de tradução, links e apresentação visual fica restrito à Action (Slim) do Catálogo correspondente, garantindo extrema flexibilidade.

## Questão
Vamos refatorar também **ProductRepository.php** eliminando o código legado, já que essa é uma classe importante e muito requisitada.

## Resposta Completa do Assistente
Essa é uma refatoração indispensável. O `ProductRepository` é uma das entidades mais consultadas do sistema e carregava um débito técnico enorme misturando regras de domínio com geração pesada de Views, links e formatações de moeda.

Para consolidar o isolamento do Domínio, eliminei os métodos visualmente acoplados (`getProductDisplayData`, `getSearchData` e `getProductThumbData`), substituindo-os pelo novo método `getFullProduct()`, que funciona como um *Aggregate Root Loader* puro: ele traz o produto com suas imagens, descontos e opções num único DTO estruturado, mas de forma bruta (floats e strings, sem formatação de HTML, URL ou moeda).

Aproveitei para ajustar o `CategoryRepository`, que dependia de um desses métodos removidos (`getProductThumbData`), para que ele também repasse os dados brutos e delegue a formatação à camada visual.
