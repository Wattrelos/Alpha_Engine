# [Correção na Injeção e Métodos do CategoryRepository em HomeAction]

**Implementação**
A correção foi realizada no arquivo [HomeAction.php](file:///var/www/html/agsonhos/core/Controller/Actions/Main/HomeAction.php) com as seguintes alterações:
1. Alteração do import e da declaração do tipo do repositório de categorias no construtor e na propriedade privada para utilizar a classe standalone correta para o ecossistema Slim: `Alpha\Model\Domain\Repositories\Slim\CategoryRepository` em vez de `Alpha\Model\Domain\Repositories\CategoryRepository`.
2. Alteração do método de carregamento das categorias em destaque de `getCategories(0)` para `getFeaturedCategories()`, que é o método correto implementado na classe de repositório Slim.

**Motivo**
A página inicial estava retornando um erro HTTP 500 porque a dependência tipada na classe `HomeAction` (`Alpha\Model\Domain\Repositories\CategoryRepository`) não correspondia à classe que foi registrada no `AppContainer` do Slim no arquivo [index.php](file:///var/www/html/agsonhos/public_html/index.php) (`Alpha\Model\Domain\Repositories\Slim\CategoryRepository`). Como resultado, o container de injeção falhava ao tentar instanciar a action. Caso a action passasse dessa etapa, ela ainda falharia ao tentar executar `getCategories(0)`, que não é definido no repositório Slim (o qual expõe `getFeaturedCategories()` com o retorno dos dados necessários e otimizados para os cards da home page).

**Benefício**
A home page voltou a renderizar com sucesso (retornando HTTP 200 OK) e as categorias em destaque com imagem e contagem de subcategorias são agora exibidas de forma rápida e otimizada por meio de uma única consulta SQL eficiente sob o ecossistema standalone da Alpha Engine rodando no Slim.

## Resposta Completa do Assistente
O motivo de a página home não estar carregando era um erro HTTP 500 no micro-framework Slim decorrente de dois problemas de acoplamento com o repositório de categorias:

1. **Incompatibilidade de Tipo na Injeção de Dependências**: O arquivo [index.php](file:///var/www/html/agsonhos/public_html/index.php) instancia e registra no `AppContainer` o repositório `Alpha\Model\Domain\Repositories\Slim\CategoryRepository` (versão standalone otimizada para o Slim, que funciona via PDO direta sem depender do Registry global do OpenCart). No entanto, o [HomeAction.php](file:///var/www/html/agsonhos/core/Controller/Actions/Main/HomeAction.php) importava e declarava no construtor a versão herdada/OpenCart do repositório (`Alpha\Model\Domain\Repositories\CategoryRepository`). Isso fazia com que o `AppContainer::resolve()` falhasse com uma `RuntimeException` informando que a dependência `CategoryRepository` de domínio não estava registrada.
2. **Chamada de Método Inexistente**: A action invocava `$this->categoryRepository->getCategories(0)` no repositório de categorias. Esse método pertence ao repositório de categorias legado. O repositório standalone do Slim possui o método específico e otimizado `getFeaturedCategories()` para alimentar os cards de categorias da vitrine da página inicial (retornando `id`, `image`, `name`, `seo_keyword`, e `subcategory_count`).

### O que foi feito para corrigir:
* **Atualização em `HomeAction.php`**:
  * Substituímos o import `Alpha\Model\Domain\Repositories\CategoryRepository` por `Alpha\Model\Domain\Repositories\Slim\CategoryRepository`.
  * Atualizamos a chamada no método `__invoke` de `$this->categoryRepository->getCategories(0)` para `$this->categoryRepository->getFeaturedCategories()`.
* **Atualização em `docs/CHANGELOG1.md`**:
  * Adicionamos uma entrada detalhando a correção sob a seção "Corrigido (Fixed)".

A página inicial do AgSonhos agora carrega com sucesso e exibe todos os departamentos/categorias na grade visual conforme o template.
