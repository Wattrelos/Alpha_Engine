# Carregamento Dinâmico de Idiomas e Processamento de Cadastro na Alpha Engine

**Implementação**
1. **Carregamento Autônomo de Idiomas**: Desenvolvemos a lógica utilitária `loadLanguageData(string $route, string $languageCode)` em [ShowRegistrationFormAction.php](file:///var/www/html/agsonhos/core/Controller/Actions/Customer/Auth/ShowRegistrationFormAction.php) para ler e mesclar dinamicamente os arrays `$_` definidos nos arquivos PHP de tradução da pasta `core/language/`.
2. **Formatação Dinâmica de Variáveis**: Implementamos a formatação de chaves complexas como `text_account_already` e `text_agree` utilizando a função `sprintf()` para substituir parâmetros por URLs válidas (ex: `/login` e termos de uso) dinamicamente.
3. **Processamento de Cadastro (POST)**: Implementamos a classe [RegisterAction.php](file:///var/www/html/agsonhos/core/Controller/Actions/Customer/Auth/RegisterAction.php) para receber dados via POST, delegar a validação e criação da conta ao `CustomerRepository` e retornar respostas JSON padronizadas para submissões AJAX.
4. **Registro de Dependência**: Adicionamos o bind de `CustomerRepository::class` no contêiner do Slim [public_html/index.php](file:///var/www/html/agsonhos/public_html/index.php).

**Motivo**
* No Slim standalone, não temos a classe de internacionalização `$this->language` do OpenCart injetada nativamente. Escrever strings de idioma diretamente nos controladores criaria duplicação de dados, e o carregador dinâmico permite aproveitar os arquivos de tradução originais.
* A Action de submissão (`RegisterAction`) estava vazia e duplicando a lógica de exibição do formulário (GET), em vez de tratar o envio de dados (POST) de forma apropriada.

**Benefício**
* **Zero Duplicidade (DRY)**: Aproveitamos 100% as traduções já definidas em [register.php](file:///var/www/html/agsonhos/core/language/pt-br/account/register.php) sem duplicá-las em arquivos PHP ou Twig.
* **Segurança e Conformidade**: A Action delega toda a integridade de dados (tamanhos de strings, restrição de e-mail duplicado) para o repositório do cliente, mantendo o controlador limpo.
* **Sem Erros de Injeção**: A resolução de dependências no Slim garante o carregamento estável de todo o fluxo de cadastro sem interrupções.

## Questão
@[/var/www/html/agsonhos/core/language/pt-br/account/register.php] @[/var/www/html/agsonhos/resources/views/pages/users/register.twig] @[/var/www/html/agsonhos/core/Controller/Actions/Customer/Auth/RegisterAction.php] Arruma para mim? Qual a melhor maneira de carregar a lista de idiomas para hidratar as variáveis Twig? Devo criar minhas próprias listas?

## Resposta Completa do Assistente
A melhor maneira absoluta é **carregar os arquivos de tradução PHP dinamicamente e injetá-los no array de dados do Twig**. Você **NÃO** deve criar suas próprias listas manuais, pois isso geraria duplicação de dados e dificultaria a manutenção de múltiplos idiomas no futuro.

### Como Resolvemos:

1. **Carregamento Dinâmico de Traduções**:
   Adicionamos o método `loadLanguageData` no controlador [ShowRegistrationFormAction.php](file:///var/www/html/agsonhos/core/Controller/Actions/Customer/Auth/ShowRegistrationFormAction.php) para ler diretamente o arquivo de idioma correspondente (ex: [register.php](file:///var/www/html/agsonhos/core/language/pt-br/account/register.php)) e transferir todas as chaves dinamicamente para o template.
   
2. **Formatação Inteligente das Strings**:
   Algumas chaves de idioma originais contêm marcadores `%s` (como links para o login e termos de uso). Formatamos esses marcadores no PHP usando a função `sprintf()` para injetar as URLs de forma amigável antes de passar as variáveis ao Twig, evitando a exibição de caracteres brutos.

3. **Implementação do Processamento (POST /cadastro)**:
   A classe [RegisterAction.php](file:///var/www/html/agsonhos/core/Controller/Actions/Customer/Auth/RegisterAction.php) foi programada para processar a requisição de cadastro. Ela delega a validação de regras de negócio ao `CustomerRepository::registerCustomer($params)` e retorna respostas de sucesso ou erro formatadas em JSON adequadas para submissões via AJAX do OpenCart.

4. **Injeção do Repositório**:
   Bindamos o `CustomerRepository::class` no `AppContainer` do Slim [public_html/index.php](file:///var/www/html/agsonhos/public_html/index.php), solucionando toda a cadeia de dependências para o processamento de cadastro.
