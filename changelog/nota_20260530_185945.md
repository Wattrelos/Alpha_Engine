# [Correção: Métodos Faltantes em Alpha\Support\Customer]

**Implementação:** Reescrita da classe `Customer` (`core/Support/Customer.php`) para adicionar os métodos `getFirstName()`, `getLastName()`, `getEmail()` e `getTelephone()`, que o `OrderRepository::collectDataFromContext()` já chamava mas que não existiam.

A implementação usa um helper privado `getLoggedUser()` que parseia o JSON de `$_SESSION['logged_user']` (gravado pelo `AuthService`). Como o objeto de sessão armazena apenas `id`, `name` e `role`, os métodos de nome decompõem o campo `name` (ex: "João Silva" → firstname="João", lastname="Silva"). Email e telephone retornam string vazia com fallback para chaves flat de sessão (`customer_email`, etc.), e o `OrderRepository` já tem o operador `?:` para complementar com os dados do endereço de pagamento da sessão.

**Motivo:** O sistema lançava `Error: Call to undefined method Alpha\Support\Customer::getFirstName()` toda vez que o fluxo de checkout chegava ao passo de criação do pedido via `OrderRepository::createFromSession()` → `collectDataFromContext()`.

**Benefício:** O checkout agora finaliza o pedido sem erros fatais. A decomposição do `name` é resiliente e o fallback para os dados de `payment_address` na sessão garante que mesmo pedidos de visitantes (não logados) preencham corretamente os campos de nome, pois `getFirstName()` retorna `''` e o operador `?:` no `OrderRepository` usa `$session->data['payment_address']['firstname']`.

## Questão

> Mas uma "ponta solta": Slim Application Error — Call to undefined method Alpha\Support\Customer::getFirstName()

## Resposta Completa do Assistente

A classe `Alpha\Support\Customer` possuía apenas os métodos `isLogged()`, `getId()` e `getGroupId()`. O `OrderRepository::collectDataFromContext()` (linha 115) chamava `$customer->getFirstName()`, `getLastName()`, `getEmail()` e `getTelephone()`, que não existiam.

**Diagnóstico:** O `AuthService::createSession()` armazena em `$_SESSION['logged_user']` um JSON com apenas `{ id, name, role }`. Não há chaves granulares como `customer_firstname` etc.

**Solução aplicada:** Reescrita de `core/Support/Customer.php` com:
- Helper privado `getLoggedUser()` que parseia `$_SESSION['logged_user']`
- `getFirstName()`: retorna a primeira palavra do campo `name`
- `getLastName()`: retorna o restante após o primeiro espaço
- `getEmail()` / `getTelephone()`: retornam o campo do objeto ou string vazia
- Fallback para chaves flat de sessão (`customer_firstname`, etc.) em todos os métodos, preservando compatibilidade futura
