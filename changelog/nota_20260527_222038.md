# [Implementação da Rota Home com Slim + Twig + Apache]

**Implementação:** Criação do caminho completo para a rota `GET /` servindo uma página HTML via Slim Framework + Twig, com Apache apontando para `public_html/`.

**Motivo:** O servidor Apache está configurado para servir `public_html/` como document root. Sem o `.htaccess` com as regras de rewrite e sem a rota definida no Slim, qualquer acesso à raiz do site resultaria em erro 404 do Apache.

**Benefício:** Caminho completo funcional e testado via CLI. A `HomeAction` implementa `ActionInterface` e está preparada para receber dados de repositórios futuramente, sem nenhuma mudança de estrutura.

---

## Questão

Estou tentando implementar uma nova rota, controller, session do zero e o meu servidor Apache está apontando para a pasta public_html/. Implemente um caminho até a página home (hello world sem banco de dados).

## Resposta Completa do Assistente

### Arquivos criados/modificados

| Arquivo | Ação | Papel |
|---|---|---|
| `public_html/.htaccess` | Criado | Rewrite rules do Apache → Slim |
| `public_html/index.php` | Reescrito | Entry point com Twig + rota `/` |
| `core/Controller/Actions/Main/HomeAction.php` | Implementado | Renderiza `pages/home.html.twig` |

### Fluxo da requisição

```
Browser GET /
  → Apache lê .htaccess
  → Redireciona para public_html/index.php
  → Slim roda addRoutingMiddleware()
  → Corresponde à rota GET '/'
  → Instancia HomeAction($twig)
  → HomeAction::__invoke() chama $twig->render('pages/home.html.twig')
  → Twig extende layouts/base.html.twig
  → Inclui components/atoms/button.twig
  → Retorna HTML completo com status 200
```

### Correção crítica no Twig

O `FilesystemLoader` estava apontando para `core/View` (pasta de templates do contexto OpenCart). Para o contexto Slim, o caminho correto é `resources/views/`, que é onde os templates Twig do novo sistema vivem.
