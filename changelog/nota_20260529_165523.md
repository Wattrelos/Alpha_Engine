# [Novo Gerenciador de Sessão Standalone (AlphaSessionHandler) na Alpha Engine]

**Implementação**:
1. **Novos Métodos no Repositório**: Adicionamos `readRaw(string $session_token): string` e `writeRaw(string $session_token, string $data, int $expire = 0): void` no repositório de domínio [SessionRepository.php](file:///var/www/html/agsonhos/core/Model/Domain/Repositories/SessionRepository.php). Estes métodos operam diretamente com strings brutas de dados, sem decodificar/codificar o JSON, permitindo que a serialização nativa do PHP atue de forma isolada. Adicionalmente, adicionamos blindagem para evitar erros de referência nula ao carregar a configuração da loja.
2. **Correção de Compatibilidade do Handler**: Corrigimos a classe [AlphaSessionHandler.php](file:///var/www/html/agsonhos/core/Session/AlphaSessionHandler.php) que implementa `\SessionHandlerInterface`. O método `read` agora chama `readRaw` (retornando a string esperada ou `""`), o `write` chama `writeRaw` (retornando `bool`), o `destroy` delega corretamente para a assinatura correta `destroy` no repositório (corrigindo o método incorreto anterior `delete`), e `gc` agora retorna `int|false`.
3. **Registro no Bootstrap e Container**: No bootstrap principal [index.php](file:///var/www/html/agsonhos/public_html/index.php), importamos as classes necessárias, instanciamos a `SessionRepository` e registramos o `AlphaSessionHandler` globalmente no PHP utilizando `session_set_save_handler($sessionHandler, true)`. Também realizamos o bind de `SessionRepository::class` no contêiner de injeção de dependências `AppContainer`.
4. **Validação**: Testamos a gravação e leitura de sessões nativas do PHP via CLI para atestar que os dados de `$_SESSION` são automaticamente serializados e persistidos na tabela `tbkk_session` do banco de dados MySQL de forma transparente.

**Motivo**:
Anteriormente, embora a Alpha Engine atuasse como uma ponte no banco de dados, o ciclo de vida da sessão ainda dependia de drivers e adaptadores sob as bibliotecas antigas do OpenCart (`system/library/session/`). O novo `AlphaSessionHandler` desacopla integralmente as sessões do framework legado, adotando os padrões do PHP moderno e a persistência via banco gerenciada pelo ORM/Mapper da Alpha Engine.

**Benefício**:
- **Conformidade Padrão**: Uso da `SessionHandlerInterface` nativa do PHP, o que simplifica o desenvolvimento e o ecossistema de middlewares do Slim.
- **Armazenamento Seguro**: As sessões do PHP nativo são guardadas diretamente no banco de dados MySQL (ou Redis caso ativo), garantindo a persistência entre requisições sem depender de arquivos físicos no servidor.
- **Desacoplamento Completo**: Eliminação total de drivers procedurais legados do OpenCart na inicialização de sessões da aplicação.

## Questão
Vamos implementar o novo gerenciador de sessão (session) para não mais depender da sessão legada do Opencart.

## Resposta Completa do Assistente
Para desacoplar integralmente a gestão de sessões das bibliotecas legadas do OpenCart e adotar um ecossistema 100% moderno na Alpha Engine, implementamos as seguintes melhorias:

1. **Adequação do Repositório (`SessionRepository`)**:
   - Criamos os métodos `readRaw` e `writeRaw` no repositório para permitir que a interface nativa do PHP grave e leia as strings de sessões sem forçar a codificação ou decodificação JSON (a serialização padrão do PHP é mantida).
   - Ajustamos o método Garbage Collector (`gc()`) para retornar o número de linhas deletadas da tabela de banco de dados (`int`).
   - Introduzimos blindagem contra referências nulas à propriedade `$this->config` para evitar erros em ambientes CLI e testes.

2. **Ajuste de Assinatura do Handler (`AlphaSessionHandler`)**:
   - Ajustamos as assinaturas e tipos de retorno de `read`, `write`, `destroy` e `gc` para serem 100% compatíveis com a `\SessionHandlerInterface` do PHP.
   - Corrigimos o método `destroy` que tentava chamar um método `delete` inexistente no repositório, direcionando-o agora corretamente para `destroy`.

3. **Configuração Global no Bootstrap**:
   - No arquivo de entrada `public_html/index.php`, registramos o `AlphaSessionHandler` como manipulador de persistência de sessão nativo do PHP chamando `session_set_save_handler()`.
   - Adicionamos a amarração (bind) de `SessionRepository::class` no `AppContainer` do Slim, permitindo sua injeção automática em controladores e outras dependências.
