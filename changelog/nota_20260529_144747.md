# Correção de Escape de HTML nos Termos de Uso do Cadastro

**Implementação**
1. **Filtro Raw do Twig**: Aplicamos o filtro `|raw` na variável `text_agree` no template [register.twig](file:///var/www/html/agsonhos/resources/views/pages/users/register.twig) na linha 87.

**Motivo**
* Por padrão, a engine de template Twig executa o escape de qualquer string impressa usando a sintaxe `{{ ... }}` para prevenir ataques de Cross-Site Scripting (XSS).
* Como o conteúdo da variável `text_agree` é composto por elementos HTML legítimos de âncora e formatação (`<a>`, `<b>`), o escape nativo exibia o código-fonte bruto na interface.

**Benefício**
* **Renderização Correta**: O texto com a âncora linkada é renderizado adequadamente como link clicável na tela de cadastro do cliente.

## Questão
O link <a> apareceu com texto: Eu li e concordo com o contrato de <a href="/index.php?route=information/information&information_id=5" class="agree"><b>Termos e Condições</b></a>, arruma para mim?

## Resposta Completa do Assistente
Corrigimos a renderização da variável de termos clicáveis no formulário de cadastro.

Por padrão de segurança, o Twig escapa qualquer tag HTML injetada via variáveis comuns. Para reverter esse comportamento e permitir que o navegador interprete e desenhe a tag `<a>` real do link, aplicamos o filtro `|raw` da seguinte forma:

```twig
<label for="input-agree" class="egen-agree-label">{{ text_agree|raw }}</label>
```

O link agora carrega e se comporta de forma totalmente clicável e correta na interface.
