# Segurança: Aplicação da Sanitização Anti-XSS no EntityMapper

**Implementação**: Incorporado o método `sanitizeInput` na classe `EntityMapper` e aplicada a filtragem da array associativa `$request` gerando uma nova variável `$safeRequest` processada no início do método `fillEntity()`.

**Motivo**: Como discutido anteriormente, proteger contra XSS dinâmico é essencial, principalmente porque a classe `EntityMapper` atua como Gateway de dados recebendo a carga bruta de requisições web. A ausência de escape antes da conversão JSON abria uma brecha de XSS Refletido e Armazenado caso administradores ou outros usuários lessem esse conteúdo.

**Benefício**: Aplica o conceito de "Security by Design". Ao limpar a matriz completa antes do processo de mapeamento entrar em ação, garante-se de forma absoluta que nenhuma entidade do Domínio (Customer, Order, Address) guardará payloads perigosos disfarçados de string, estendendo essa garantia até as tabelas de banco de dados e futuras exibições nas Views (Twig).

## Resposta Completa do Assistente
Excelente! Com a classe em mãos, podemos aplicar a nossa trava de segurança diretamente no fluxo de entrada de dados do `EntityMapper`.

Para implementar isso, nós vamos criar o método `sanitizeInput` na classe e atualizar o `fillEntity` para processar a variável `$request` antes mesmo de a reflexão (Reflection) iniciar. Dessa forma, nós garantimos que todo e qualquer valor acessado por `$safeRequest` durante a hidratação já esteja perfeitamente filtrado contra injeções de script (XSS).

(Foram aplicadas as inclusões do método `sanitizeInput` recursivo usando `htmlspecialchars` e a refatoração do array lido no laço do método `fillEntity` apontando agora para `$safeRequest` nas dependências do `EntityMapper.php`).
