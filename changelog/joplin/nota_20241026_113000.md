# Correção de Bug: Variáveis de Idioma Vazias no Controlador Edit

**Implementação**: Substituição do método legado de carregamento de linguagem `$this->load->language('account/edit');` pelo injetor automático da Alpha Engine `$this->loadLanguageData('account/edit', $data);` no método `index()` do controlador `catalog/controller/account/edit.php`.

**Motivo**: O controlador estava parcialmente refatorado. O uso do método legado apenas registrava os textos no dicionário interno (`$this->language`), mas falhava em popular o array `$data`. Como resultado, todas as variáveis interpoladas no `edit.twig` (ex: `{{ button_back }}`, `{{ entry_firstname }}`) estavam sendo avaliadas como nulas durante a renderização.

**Benefício**: Restabelece todos os textos, rótulos (labels) e botões do formulário de edição de conta. O código fica homogeneizado com os demais Controladores já modernizados para a arquitetura Alpha (como `account.php` e `register.php`), garantindo injeção transparente de dicionários em Views.

## Questão
Pode verificar se o Controller **edit.php** está com problemas? Vou enviar o código dele.

## Resposta Completa do Assistente
Analisando o código do seu arquivo `catalog/controller/account/edit.php`, identifiquei perfeitamente o problema! 

Durante a refatoração para a **Alpha Engine**, o método `index()` do `edit.php` não foi atualizado para usar o novo injetor automático de idiomas. Ele ainda estava usando o carregamento legado (`$this->load->language()`), que apenas carrega as traduções na memória, mas **não as repassa automaticamente para o array `$data`**. 

Como consequência, não apenas o `button_back` e `button_continue` estavam vazios, mas provavelmente **todas as outras variáveis de texto da página** (como `entry_firstname`, `text_your_details`, etc.) não estavam sendo impressas no seu Twig.

Veja abaixo o patch para corrigir isso, substituindo a chamada legada pelo método inteligente `$this->loadLanguageData()`.
