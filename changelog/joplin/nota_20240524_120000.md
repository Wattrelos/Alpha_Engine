# Nova Implementação: Automação de Nomenclatura Dinâmica de Notas

**Implementação**: Criação de um utilitário em Bash (`tests/scripts_uteis/criar_nota_gemini.sh`) para capturar a data do relógio local da máquina host (Debian) e gerar o arquivo de documentação Markdown com o prefixo temporal correto (`YYYYMMDD_HHMMSS`).

**Motivo**: Como LLMs não possuem acesso nativo direto ao relógio de hardware do ambiente do usuário (rodando via extensão da IDE em vez de processo local iterativo), os nomes de arquivos gerados nas respostas do chat sofriam de alucinações temporais ou ficavam ancorados nas datas lidas nos arquivos de contexto anteriores (ex: 20241026).

**Benefício**: Evita a colisão de arquivos de notas técnicas, elimina a defasagem cronológica no registro de documentação do repositório e otimiza o fluxo de trabalho, permitindo que a IA receba o nome do arquivo gerado pelo SO ao invés de ter que adivinhar a data.

## Questão
As notas estão sendo gravadas com data defasada, como faço para o Gemini ter acesso a data atual do sistema?

## Resposta Completa do Assistente
Olá! Essa é uma excelente pergunta e toca em uma limitação técnica fundamental de como assistentes baseados em Inteligência Artificial funcionam dentro das IDEs. Como um modelo de linguagem, eu não estou "rodando" no seu SO Debian podendo disparar o comando `date`. 

Se a extensão do VSCodium não injeta a data no prompt de sistema, eu me baseio no contexto e posso gerar datas defasadas. Para contornar, recomendo duas abordagens:
1. Passar a data manualmente no prompt (Ex: "A data atual é YYYYMMDD_HHMMSS, gere a nota").
2. Utilizar um script Bash local que cria o arquivo com a data precisa do hardware, e então pedir para que eu apenas preencha o conteúdo do arquivo recém-gerado.

Foi desenvolvido e anexado o script `criar_nota_gemini.sh` para cobrir o segundo caso de uso.
