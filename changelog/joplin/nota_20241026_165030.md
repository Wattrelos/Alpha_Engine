# Refatoração: Migração de Assinaturas para a Alpha Engine

**Implementação**: Criação do `SubscriptionRepository` para abrigar a lógica da camada Conta do Cliente relacionada a planos recorrentes (Assinaturas). Os métodos complementares de leitura de pedidos da assinatura foram anexados ao `OrderRepository`. O mapa foi registrado no `AlphaContainer` e o arquivo legado foi arquivado.

**Motivo**: O controlador de assinaturas (`account/subscription.php`) já utilizava o padrão moderno de injeção da Alpha Engine para acionar o `SubscriptionRepository`, porém o arquivo não existia. Isso impossibilitava listar assinaturas, renderizar os produtos dos planos, visualizar histórico de recorrências e carregar a guia de pedidos atrelados.

**Benefício**: Descontinuação integral de mais um modelo OpenCart na camada Account, unificando a extração dos dados (Legacy Bridges) dentro da interface base e preparando a infraestrutura para futuras extensões de processadores de pagamento que dependem de regras centralizadas para renovação ou suspensão de serviços.

## Questão
Identifique e refatore o modelo de Assinaturas **subscription.php**  implementando o SubscriptionRepository na Alpha Engine.

## Resposta Completa do Assistente
Perfeito! O controlador de assinaturas `catalog/controller/account/subscription.php` já efetuava as chamadas por injeção ao `SubscriptionRepository` via Alpha Engine, porém, assim como as outras áreas recém-migradas da conta do cliente, faltava o Repositório de Domínio para absorver essas regras de acesso ao banco (Legacy Bridges) e dar suporte às consultas.
Também identifiquei que a funcionalidade de listagem de pedidos ligados a uma assinatura recorrente (`getOrdersBySubscriptionId`) acionava o `OrderRepository`, portanto, precisei adicionar essas consultas lá também.
