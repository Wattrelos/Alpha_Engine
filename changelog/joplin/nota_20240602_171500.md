# Automação: Varredura e Arquivamento de Models Legados em Design

**Implementação**: Acionamento do script bash de varredura `find_unused_models.sh` via terminal para verificar a ociosidade de arquivos legados de modelo na rota `catalog/model/design/` (e demais subdiretórios) e renomeá-los preventivamente de `.php` para `.old`.

**Motivo**: Com as recentes refatorações de controladores de catálogo, componentes de layout e módulos de extensão (como o `banner.php`) para a adoção da Alpha Engine (usando Repositórios de Domínio no lugar de `load->model()`), antigas classes de modelo de design se tornaram "dead code". Identificá-las e inativá-las manualmente é um processo custoso e passível de erro humano.

**Benefício**: Automatiza a higienização da arquitetura legada. Reduz o tamanho do projeto escaneável pela IDE, elimina ruído de auto-completar do VSCodium para classes obsoletas e garante a integridade da aplicação por arquivar (inativando a extensão .php) em vez de deletar fisicamente, permitindo fácil rollback em caso de falso-positivo.

## Questão
Excelente! Podemos executar aquele script `find_unused_models.sh` que criamos anteriormente para checar se outras models em design/ já podem virar .old?

## Resposta Completa do Assistente
Com certeza! Como acabamos de neutralizar a última dependência do módulo de banners, o caminho está livre para rodarmos a varredura e limparmos o restante das models obsoletas da pasta de design (como `layout.php`, `theme.php`, `translation.php`, etc., caso existam e não possuam mais referências).

Abra o terminal integrado do seu VSCodium e execute o nosso script de automação:

```bash
./find_unused_models.sh
```

*(Dica: Se o script não executar direto, lembre-se de conferir se as permissões ainda estão ativas com `chmod +x find_unused_models.sh`)*.

Assim que rodar o script, ele varrerá iterativamente os arquivos, cruzará com as menções no seu código e arquivará automaticamente as models esquecidas renomeando-as de `.php` para `.old`.
