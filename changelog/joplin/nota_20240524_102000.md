# Refatoração: Adaptação de Reward API para o Padrão Entity e Repository

**Implementação**: Refatoração das extensões `admin/controller/api/reward.php` e `catalog/controller/api/reward.php`. O controlador do Admin substituiu a model legada de vendas (`model_sale_order`) pelo `OrderRepository` e trocou a extração sintática de arrays (`$order_total['title']`) pelo acesso puramente orientado a objetos (`$order_total->getTitle()`, `$order_total->getCode()`). No Catálogo, injetou-se nativamente o `CartRepository`, removendo o uso dos serviços legados de sessão (`$this->cart`). Ambos os controladores passaram a estender o `BaseController`.

**Motivo**: Ao transicionar os mapeadores de banco de dados (Models) para as Entidades da Alpha Engine, qualquer leitura que esperasse um Array resultaria fatalmente na interrupção do sistema (*White Screen of Death* ou HTTP 500) do tipo "Cannot use object of type Entity as array". 

**Benefício**: Evita quebras críticas na interface do Administrador durante o carregamento dos detalhes de conversão de pontuação dos pedidos. Além disso, purifica as lógicas subjacentes das APIs para abraçarem 100% o Design Pattern do sistema novo.

## Resposta Completa do Assistente
Excelente observação! Ao vasculhar a API do Reward (`reward.php`) na área do Admin e do Catálogo (extensões), identifiquei exatamente a vulnerabilidade que você pontuou.

No arquivo `/extension/opencart/admin/controller/api/reward.php`, o sistema ainda invocava a *model* legada de Vendas (`$this->model_sale_order`) e, mais criticamente, tentava acessar a propriedade `title` via sintaxe de array associativo (`$order_total['title']`). Como estamos migrando tudo para a Orientação a Domínio através do `OrderRepository`, esse código geraria um *Fatal Error* ("Cannot use object of type Entity as array") assim que o Repositório devolvesse a Entidade puramente hidratada.

Já no lado do catálogo (`/extension/opencart/catalog/controller/api/reward.php`), não havia acesso indevido à Entidade, mas o controlador ainda carregava o acoplamento pesado do serviço legado do carrinho (`$this->cart`). 

Para resolver definitivamente o escopo da API, refatorei ambos os arquivos. Os controladores agora estendem o `BaseController`, recebem a injeção nativa dos repositórios (`OrderRepository` e `CartRepository`) e acessam as propriedades estritamente pelos getters das Entidades (`getCode()`, `getTitle()`).
