# Refatoração: Validações Estritas em Campos Personalizados (Custom Fields)

**Implementação**: Refatoração do bloco de validação de `custom_fields` no método `save()` do controlador `catalog/controller/account/edit.php`. Substituição da checagem genérica `empty()` por uma verificação dinâmica com suporte a _Type-Safety_, utilizando `is_array` e `trim()`. Inclusão de conversão forçada `(string)` na submissão de valores literais para o validador de Regex.

**Motivo**: A implementação original permitia _bypass_ de regras de obrigatoriedade caso o usuário preenchesse um campo texto/área apenas com espaços em branco (visto que `empty(" ")` retorna falso no PHP). Adicionalmente, faltava resiliência em ambiente PHP 8.x: a injeção intencional de arrays em validações regex causaria exceções fatais (`TypeError`).

**Benefício**: Mitigação de lixo no banco de dados, protegendo o CRM e garantindo que os clientes preencham adequadamente os campos requeridos (como CPF, CNPJ ou Celular customizados). Aumenta substancialmente a robustez da API contra requisições malformadas.

Analisando o método `save()` do seu `catalog/controller/account/edit.php`, a validação dos `custom_fields` está utilizando a implementação padrão e básica do OpenCart. Essa abordagem esconde **dois problemas silenciosos** na validação:

1. **Bypass de Campos Obrigatórios**: A função `empty()` nativa do PHP considera uma string contendo apenas um espaço em branco (`" "`) como **não-vazia**. Ou seja, um cliente pode facilmente pular um campo obrigatório (como um CPF ou Celular customizado) apenas digitando a barra de espaço.
2. **Quebra de Tipo (TypeError) no PHP 8+**: Se um campo for do tipo `checkbox` (que envia um Array no POST) mas sofrer injeção no DOM alterando-o para `text`, o `oc_validate_regex()` tentará processar um Array como se fosse String, resultando em um erro fatal 500 no backend.

Para resolver isso, vou te enviar um patch substituindo aquele bloco por uma validação estrita (Type-Safe). Nós checaremos exatamente se o valor é um Array ou String, aplicaremos o `trim()` para podar espaços vazios e garantiremos o tipo na hora de rodar as expressões regulares.
