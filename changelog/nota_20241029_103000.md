# Refatoração: Adaptação Visual e Orquestração no ShowCategoryAction

**Implementação**: Refatoração do `ShowCategoryAction` injetando a classe `Registry` via construtor de injeção de dependências (DI). Toda a rotina visual previamente extraída do `CategoryRepository` (resize de imagem, formatação visual de preços aplicando taxas e descontos e montagem iterativa das URLs de limitação e ordenação) foi mapeada dentro desta action usando o nativo `RouteParser` da framework Slim.

**Motivo**: Estabelecer e concretizar a padronização *Skinny Controller* focada em *Domain-Driven*. Os dados brutos vindos da base de dados são recebidos limpos pela Action, que então assume seu papel de "Presenter", acionando as classes de cálculo de moedas, utilitários de imagem e roteadores físicos da aplicação (Slim Router) para abastecer estritamente a *View* com informações devidamente tratadas, blindando falhas no backend.

**Benefício**: O ecossistema está 100% estabilizado e flexível. Caso a Engine migre futuramente para outras mecânicas de *front-end* (como React/Vue) que não consumam o `ShowCategoryAction`, mas consumam nativamente o `CategoryRepository` como *API*, todos os dados brutos estarão disponíveis de imediato sem a dependência ou poluição dos utilitários visuais legados do OpenCart na saída JSON.
