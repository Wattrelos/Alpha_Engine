# [Abandono do OpenCart\Registry — Nova Camada de Repositories PDO-based]

**Implementação:** Criação de `Alpha\Model\Domain\Repositories\Slim\AbstractRepository` e `CategoryRepository` — nova base arquitetural que substitui a dependência do `OpenCart\Registry` por PDO direto. Integração completa com `HomeAction`, `header.twig` e Twig global de categorias.

**Motivo:** O `OpenCart\Registry` acoplava todos os Repositories ao bootstrap do OpenCart, tornando-os inutilizáveis no contexto do Slim. A nova base Slim usa somente PDO, `language_id`, `store_id` e `prefix` — completamente independente do framework legado.

**Benefício:** Qualquer novo Repository do sistema Slim herda de `AbstractSlimRepository` e funciona sem nenhuma dependência do OpenCart. O `CategoryMenuService` foi absorvido pelo `CategoryRepository` (agora com 3 métodos: `getMenuTree`, `getFeaturedCategories`, `findById`). As categorias do menu são carregadas como Twig global — 1 query por requisição, disponível em todos os templates sem acoplamento com nenhuma Action específica.

## Questão

Decidi abandonar o OpenCart\Registry e retomar o controle dos Repositories. Vamos implementar a nova tela inicial home, começando pelo CategoryRepository.

### Padrão de Criação de Novos Repositories

```php
// Todo novo repository do Slim segue este padrão:
class ProductRepository extends AbstractRepository
{
    public function getFeatured(int $limit = 6): array
    {
        return $this->fetchAll("SELECT ... FROM {$this->prefix}product ...", [...]);
    }
}

// Registro em index.php:
$container->bind(ProductRepository::class, new ProductRepository($pdo, 2, 0, DB_PREFIX));
```

### Observação: bug PDO/MariaDB no LIMIT

`PDO::ATTR_EMULATE_PREPARES = false` no MariaDB não aceita bound parameters em `LIMIT`. Solução: inteiro validado por `max(1, (int)$limit)` injetado diretamente na string SQL (sem risco de SQL injection pois é PHP int).
