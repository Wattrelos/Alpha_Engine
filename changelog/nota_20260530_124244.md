# Análise de Viabilidade Técnica para Migração de PKs/FKs para BIGINT (Alpha Engine)

**Implementação**:
- Elaboração do estudo detalhado de viabilidade em [pks_fks_bigint_feasibility.md](file:///var/www/html/agsonhos/docs/pks_fks_bigint_feasibility.md) analisando o comportamento do tipo de dado de inteiros sob PHP 8.4 (em ambientes de 64 bits), no MySQL e em serializações JSON com o JavaScript.
- Identificação da ausência de impacto no runtime do ORM nativo da Alpha Engine, pois as leituras e hidratações efetuadas pelo [DataAccessObject](file:///var/www/html/agsonhos/core/Model/DataAccessObject/DataAccessObject.php) realizam coerção direta para o tipo `(int)` (que já opera de forma nativa como 64 bits assinados em sistemas operacionais modernos de 64 bits).
- Mapeamento de recomendações de migração em banco de dados InnoDB (como o desligamento temporário de foreign keys checks).
- Inclusão do novo estudo no índice do [README.md](file:///var/www/html/agsonhos/README.md).

**Motivo**:
- Validar a segurança e a integridade da aplicação antes de realizar alterações estruturais de tipo de dado nas chaves primárias e estrangeiras do banco de dados, visando adequar o sistema às melhores práticas de escalabilidade do mercado.

**Benefício**:
- **Segurança de Decisão**: Prevenção de potenciais erros de integridade referencial ou truncamento de dados em produção.
- **Rastreabilidade**: Documentação completa e clara das limitações de precisão numérica existentes entre MySQL, PHP e JavaScript.

## Questão
Pretendo alterar as PKs e FKs nas tabelas do banco de dados de INT(11) para BIGINT (ou outro tipo recomendado) para ajustar o Alpha Engine aos boas práticas de mercado. Vamos fazer uma análise de viabilidade para ver se é seguro mudar os tipos nas tabelas do BD.

## Resposta Completa do Assistente
Realizei a análise de viabilidade técnica detalhada sobre a alteração das chaves primárias (PKs) e chaves estrangeiras (FKs) de `INT(11)` para `BIGINT` (ou `BIGINT(20)`) e criei o documento de documentação correspondente em [pks_fks_bigint_feasibility.md](file:///var/www/html/agsonhos/docs/pks_fks_bigint_feasibility.md).

### Resumo dos Resultados:
1. **PHP (Alpha Engine ORM)**: É **100% seguro**. Em sistemas de 64 bits, o tipo `int` do PHP é assinado e possui 64 bits, combinando perfeitamente com o `BIGINT` do MySQL. Como o nosso [DataAccessObject.php](file:///var/www/html/agsonhos/core/Model/DataAccessObject/DataAccessObject.php) usa cast explícito para `(int)`, não haverá perda de precisão ou erro de hidratação.
2. **Banco de Dados (MySQL / MariaDB)**: A migração é recomendada para alta escala (evita o estouro do limite máximo de 2 bilhões de IDs do `INT` normal). Contudo, exige que PKs e FKs correspondentes sejam alteradas juntas, o que requer desativar temporariamente o `FOREIGN_KEY_CHECKS` durante a execução do DDL.
3. **Limitação em JavaScript**: O JavaScript lê números inteiros de forma segura até `9.007.199.254.740,991` (`Number.MAX_SAFE_INTEGER`). Como as chaves autoincrementais crescem sequencialmente a partir de 1, não há risco prático de estouro de precisão no frontend em JSON por séculos.
