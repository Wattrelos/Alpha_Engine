# [Migração de Rotas Legadas do OpenCart para Rotas Modernas e SEO-Friendly no Slim]

Este documento apresenta uma análise profunda sobre a viabilidade, a estratégia e as abordagens técnicas necessárias para migrar o sistema de roteamento baseado em query parameters do OpenCart para uma estrutura moderna, amigável (SEO) e standalone na Alpha Engine utilizando o Slim Framework.

**Implementação**
A migração de rotas envolve a desativação completa do roteamento do OpenCart (`index.php?route=...`) e a adoção do sistema de rotas nativo do Slim Framework. A implementação baseia-se em três pilares fundamentais:
1. **Roteamento Dinâmico de SEO (Dynamic Route Dispatcher):** Uso de uma rota coringa (catch-all) integrada com o `SeoUrlRepository` para resolver slugs virtuais diretamente do banco de dados para controladores específicos.
2. **Internacionalização no Path (Language Routing Prefix):** Passagem do código do idioma na própria estrutura de diretórios virtuais da URL (ex: `/{lang}/carrinho` ou `/{lang}/produto/{slug}`), substituindo o query parameter `&language=pt-br`.
3. **Mapeador Reverso de Links (UrlGenerator) e Redirecionamento 301 de Compatibilidade:** Criação de um serviço para gerar URLs amigáveis dinamicamente nas Views Twig e um middleware de fallback para redirecionar de forma permanente (301) conexões antigas do OpenCart que chegam ao servidor.

**Motivo**
As URLs legadas do OpenCart (`route=product/product&product_id=40&language=pt-br`) geram problemas significativos para SEO, legibilidade e cache:
* **Indexabilidade:** URLs contendo múltiplos parâmetros dinâmicos são mais difíceis de rastrear e indexar perfeitamente.
* **Duplicação de Conteúdo:** Sem um tratamento rigoroso e canonicalização, a mesma página pode ser exibida sob múltiplos parâmetros de query.
* **Aderência Standalone:** Manter parâmetros como `route=...` preserva o acoplamento conceitual com a engine que foi descartada. Um sistema de rotas limpo no Slim consolida a Alpha Engine como um motor verdadeiramente independente e moderno.

**Benefício**
* **Otimização de SEO (Rankings Superiores):** URLs contendo palavras-chave estruturadas (ex: `/pt-br/produto/iphone-13-128gb`) aumentam a relevância orgânica e a CTR (Click-Through Rate) nos resultados de busca.
* **Roteamento Limpo e Rápido:** Slim resolve rotas com expressões regulares compiladas em altíssima velocidade.
* **Compatibilidade 100% Preservada:** Mecanismos de busca e links externos legados não serão quebrados, pois o redirecionador 301 transferirá a autoridade das páginas (link juice) para as novas rotas.
* **Internacionalização Robusta:** Suporte a múltiplos idiomas na URL indexável, isolando a persistência por sessão para fins logísticos (como moedas e carrinhos), mantendo o crawler do Google feliz.

## Questão
Já que estamos revazendo a Engine de forma standalone, faça uma análise se há a possibilidade de migração das rotas Opencart para rotas que utilizam práticas modernas de URL, SEO, etc.

## Resposta Completa do Assistente

Sim, a migração para rotas modernas, limpas e focadas em SEO é **perfeitamente viável** e representa o passo lógico seguinte no amadurecimento da **Alpha Engine** como um sistema standalone.

Abaixo, detalhamos a análise estratégica e o plano de arquitetura técnica recomendado para realizar essa migração no Slim Framework sem quebrar a retrocompatibilidade de links antigos que já estejam indexados no Google.

### 1. Novo Padrão de URLs vs. Legado

| Tipo de Página | URL Legada OpenCart | Nova URL Moderna (Alpha/Slim) |
| :--- | :--- | :--- |
| **Página Inicial** | `/index.php?route=common/home` | `/` ou `/{lang}` |
| **Login** | `/index.php?route=account/login` | `/{lang}/login` |
| **Cadastro** | `/index.php?route=account/register` | `/{lang}/cadastro` |
| **Carrinho** | `/index.php?route=checkout/cart` | `/{lang}/carrinho` |
| **Checkout** | `/index.php?route=checkout/checkout` | `/{lang}/checkout` |
| **Detalhes de Produto** | `/index.php?route=product/product&product_id=40` | `/{lang}/produto/{slug}` *ou* `/{lang}/{slug}` |
| **Listagem de Categoria** | `/index.php?route=product/category&path=20` | `/{lang}/categoria/{slug}` *ou* `/{lang}/{slug}` |
| **Página Institucional** | `/index.php?route=information/information&information_id=4` | `/{lang}/pagina/{slug}` *ou* `/{lang}/{slug}` |

> [!NOTE]
> Conforme alinhado anteriormente, manter a variável de idioma (`{lang}`) explícita na URL é fundamental para a otimização de SEO. Isso garante que os bots de indexação (como Googlebot) possam indexar separadamente a versão em Português (`/pt-br/produto/iphone`) e Inglês (`/en/product/iphone`), já que crawlers não armazenam estado de cookie ou sessão.

### 2. Estratégia de Internacionalização no Slim

Para gerenciar o prefixo de idioma na URL de forma automatizada no Slim Framework, podemos encapsular as rotas em um **Grupo de Rotas** com um parâmetro opcional ou obrigatório de idioma:

```php
// public_html/index.php

use Slim\Routing\RouteCollectorProxy;

$app->group('/{lang:pt-br|en|es}', function (RouteCollectorProxy $group) use ($container) {
    
    // Rotas Estáticas
    $group->get('/login', function ($request, $response) use ($container) {
        return $container->get(ShowLoginFormAction::class)($request, $response, []);
    });
    
    $group->get('/carrinho', function ($request, $response) use ($container) {
        return $container->get(CartAction::class)($request, $response, []);
    });

    // Rotas Dinâmicas de Domínio (Abordagem com Prefixos)
    $group->get('/produto/{slug}', function ($request, $response, $args) use ($container) {
        $args['action_class'] = ProductDetailAction::class;
        return $container->get(MainRouterController::class)->handle($request, $response, $args);
    });

    $group->get('/categoria/{slug}', function ($request, $response, $args) use ($container) {
        $args['action_class'] = CategoryDetailAction::class;
        return $container->get(MainRouterController::class)->handle($request, $response, $args);
    });
});
```

Um middleware de escopo global pode analisar o parâmetro `{lang}` da requisição ativa e configurar o idioma de tradução e a moeda correspondente na Alpha Engine de forma invisível para os controladores:

```php
// core/Auth/Middleware/LanguageSubdomainMiddleware.php

namespace Alpha\Auth\Middleware;

use Psr\Http\Message\ServerRequestInterface as Request;
use Psr\Http\Server\RequestHandlerInterface as Handler;
use Psr\Http\Message\ResponseInterface as Response;
use Slim\Routing\RouteContext;

class LanguageMiddleware
{
    public function __invoke(Request $request, Handler $handler): Response
    {
        $routeContext = RouteContext::fromRequest($request);
        $route = $routeContext->getRoute();
        
        if ($route) {
            $lang = $route->getArgument('lang', 'pt-br');
            
            // Define o idioma no contexto atual da aplicação (config, translation, etc.)
            // TranslationRepository::setLocale($lang);
        }
        
        return $handler->handle($request);
    }
}
```

### 3. Abordagens para Roteamento Dinâmico de SEO URLs

No e-commerce, muitas vezes o lojista prefere URLs "puras" sem `/produto/` ou `/categoria/` no meio, por exemplo: `http://loja.com/pt-br/iphone-13` (em vez de `/pt-br/produto/iphone-13`). Temos duas formas de resolver isso no Slim:

#### Abordagem A: Prefixos Explícitos (Recomendado para Performance)
* **Estrutura:** `/pt-br/produto/{slug}` e `/pt-br/categoria/{slug}`.
* **Funcionamento:** O Slim descobre de imediato para qual controlador enviar a requisição baseando-se no path estático. O controlador de produto busca o slug na tabela `seo_url` (ou diretamente na tabela de produtos se usarmos um campo `slug` indexado).
* **Prós:** Altíssima performance de roteamento. Sem ambiguidades de rotas.
* **Contras:** A URL fica ligeiramente mais longa.

#### Abordagem B: Rota Coringa Dinâmica (Dynamic Catch-All)
* **Estrutura:** `/{lang}/{slug}` registrada como a **última rota** do arquivo de bootstrap.
* **Funcionamento:** Se nenhuma rota estática bater (como `/login` ou `/carrinho`), o Slim cai nesta rota genérica. O controlador `DynamicRouteAction` intercepta o parâmetro `{slug}`, consulta o `SeoUrlRepository`, e redireciona internamente para a Action adequada.
* **Exemplo de Código da Rota Catch-All:**

```php
// No final do arquivo public_html/index.php
$app->get('/{lang}/{slug}', function ($request, $response, $args) use ($container) {
    $seoRepository = $container->get(SeoUrlRepository::class);
    $slug = $args['slug'];
    
    // Resolve o slug (ex: "iphone-13" -> key = "product_id", value = "40")
    $queryStr = $seoRepository->getQueryByKeyword($slug, 0, 2); // Exemplo de store e lang
    
    if (empty($queryStr)) {
        throw new HttpNotFoundException($request, "URL amigável não encontrada.");
    }
    
    parse_str($queryStr, $resolvedParams);
    
    if (isset($resolvedParams['product_id'])) {
        $args['id'] = $resolvedParams['product_id'];
        return $container->get(ProductDetailAction::class)($request, $response, $args);
    }
    
    if (isset($resolvedParams['category_id'])) {
        $args['id'] = $resolvedParams['category_id'];
        return $container->get(CategoryDetailAction::class)($request, $response, $args);
    }
    
    if (isset($resolvedParams['information_id'])) {
        $args['id'] = $resolvedParams['information_id'];
        return $container->get(InformationDetailAction::class)($request, $response, $args);
    }
    
    throw new HttpNotFoundException($request);
});
```

### 5. Preservação de Links Antigos (Redirecionamento 301)

Para não perder os rankings do Google das páginas já indexadas, implementamos um Middleware no Slim que detecta requisições contendo parâmetros legados do OpenCart e realiza um redirecionamento HTTP 301 Permanente para a nova URL limpa correspondente:

```php
// core/Auth/Middleware/LegacyRouteRedirectMiddleware.php

namespace Alpha\Auth\Middleware;

use Psr\Http\Message\ServerRequestInterface as Request;
use Psr\Http\Server\RequestHandlerInterface as Handler;
use Psr\Http\Message\ResponseInterface as Response;
use Slim\Psr7\Response as SlimResponse;

class LegacyRouteRedirectMiddleware
{
    private $seoRepository;

    public function __construct(SeoUrlRepository $seoRepository)
    {
        $this->seoRepository = $seoRepository;
    }

    public function __invoke(Request $request, Handler $handler): Response
    {
        $queryParams = $request->getQueryParams();
        
        // Exemplo: ?route=product/product&product_id=40&language=pt-br
        if (isset($queryParams['route'])) {
            $route = $queryParams['route'];
            $lang = $queryParams['language'] ?? 'pt-br';
            
            if ($route === 'product/product' && isset($queryParams['product_id'])) {
                $keyword = $this->seoRepository->getKeywordByQuery('product_id', $queryParams['product_id'], 0, 2);
                
                if ($keyword) {
                    $response = new SlimResponse();
                    return $response
                        ->withHeader('Location', "/{$lang}/{$keyword}")
                        ->withStatus(301); // Redirecionamento permanente para SEO
                }
            }
            // Mapeamentos adicionais para categorias e institucionais...
        }
        
        return $handler->handle($request);
    }
}
```

### Conclusão e Próximo Passo Recomendado

A migração é perfeitamente viável, limpa e altamente recomendada. Ela consolida as melhores práticas de desenvolvimento web moderno na Alpha Engine, elimina as URLs de formato antiquado e dá controle total de rota para a aplicação.

O próximo passo ideal seria estruturar o **Grupo de Rotas de Idioma** e implementar o **LegacyRouteRedirectMiddleware** para que a transição ocorra de forma segura e transparente para a base de clientes do e-commerce.
