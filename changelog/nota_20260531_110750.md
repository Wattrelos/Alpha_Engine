# [Análise de Recursos para Implementação de Faceted Search]

**Implementação**
Para habilitar a busca facetada de forma completa, os seguintes passos de refatoração devem ser realizados:
1. **Modificação no Controller (`ShowCategoryAction.php`):**
   - Adicionar o `ManufacturerRepository` no construtor da action (injetado via container DI).
   - Capturar os parâmetros da query string (`category`, `manufacturer`, `price_min`, `price_max`, `rating`) e passá-los no array de dados `$filterData` para o repositório.
   - Alimentar a view com `lista_categorias` (via `categoryRepository->getCategories(0)`), `lista_manufacturers` (via `manufacturerRepository->getManufacturers()`), e `filtros_ativos`.
2. **Modificação no Repositório (`CategoryRepository.php`):**
   - Repassar as chaves de filtros facetados para a chamada de `$productRepository->getProducts($productFilter)` e `$productRepository->getTotalProducts($productFilter)`.
3. **Modificação no Data Mapper (`ProductMapper.php`):**
   - Atualizar os métodos `getProducts` e `getTotalProducts` para aplicar as cláusulas `WHERE` condicionais na `QueryBuilder`:
     - Cláusula `IN` para múltiplos fabricantes (`filter_manufacturers`).
     - Cláusula `IN` para múltiplas subcategorias (`filter_categories`).
     - Filtros de preço (`price >= ?` e `price <= ?`).
     - Subquery para média de avaliação (`AVG(rating) >= ?`).

**Motivo**
Atualmente, as consultas de banco de dados suportam apenas filtragem por um único ID de categoria ou fabricante (`filter_category_id` e `filter_manufacturer_id`). A estrutura da Alpha Engine (SLIM standalone + Data Mappers) é altamente modular e possui repositórios dedicados para marcas e categorias, tornando viável a implementação limpa e de alto desempenho (evitando consultas N+1).

**Benefício**
A implementação completa trará uma navegação fluida aos usuários, permitindo refinar resultados por múltiplas características simultaneamente, maximizando a conversão e alinhando o backend com a nova UI premium facetada.

### O Plano de Ação para Implementação:

#### 1. No Controller (`ShowCategoryAction.php`)
Injetar o repositório de fabricantes e alimentar a view do Twig:
```php

// Capturar os query params e popular filtros_ativos:

    'price_max'    => $queryParams['price_max'] ?? '',
    'rating'       => $queryParams['rating'] ?? ''

```

#### 2. No CategoryRepository (`CategoryRepository.php`)
Repassar esses dados na chamada de busca dos produtos:
```php
$productFilter = [
    'filter_category_id'   => $categoryId,

    'filter_manufacturers' => $filterData['manufacturers'] ?? [],
    'filter_price_min'     => $filterData['price_min'] ?? null,
    'filter_price_max'     => $filterData['price_max'] ?? null,
    'filter_rating'        => $filterData['rating'] ?? null,
    // ...

```

#### 3. No ProductMapper (`ProductMapper.php`)
Incrementar os métodos `getProducts` e `getTotalProducts` para injetar cláusulas WHERE dinâmicas na `QueryBuilder`:
```php
// Filtro por múltiplos fabricantes:
if (!empty($data['filter_manufacturers'])) {
    $manufacturers = array_map('intval', $data['filter_manufacturers']);
    $placeholders = implode(',', array_fill(0, count($manufacturers), '?'));
    $query->where("p.manufacturer_id IN ($placeholders)", $manufacturers);
}
// Filtro por faixas de preço:
if (!empty($data['filter_price_min'])) {
    $query->where("p.price >= ?", [(float)$data['filter_price_min']]);
}
// Filtro por avaliação:
if (!empty($data['filter_rating'])) {
    $query->where("(SELECT AVG(r.rating) FROM " . DB_PREFIX . "review r WHERE r.product_id = p.id AND r.status = 1) >= ?", [(int)$data['filter_rating']]);
}
```
