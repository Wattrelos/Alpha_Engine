# [Implementação: Listagem de Pedidos do Usuário Logado]

**Implementação:** Redesign completo do template `resources/views/pages/users/accounts/orders.twig` com UI premium dark mode. O controller `OrdersAction` e o `OrderRepository` já estavam funcionais — o pipeline completo é:

1. **Rota** `/pt-br/account/orders` (com `SessionMiddleware`) → `OrdersAction::__invoke()`
2. **Controller** (`OrdersAction`) chama `OrderRepository::getOrders(0, 20)` → `OrderMapper::getOrdersArray(customer_id, ...)`
3. **Customer ID** resolvido por `$this->customer->getId()` via `AbstractRepository::__get()` → `registry->get('customer')` → `Alpha\Support\Customer::getId()` → `$_SESSION['customer_id']` ou `logged_user->id`
4. **Template** redesenhado com tabela premium, status pills semânticos e estado vazio

**Template features:**
- Hero com breadcrumb e título
- Stats bar mostrando total de pedidos
- Tabela com glassmorphism card, hover states, status pills coloridos por estado (amarelo = processando, verde = completo, vermelho = cancelado, azul = enviado)
- Empty state com CTA para explorar produtos
- 100% responsivo (colunas de data e texto do botão colapsam em mobile)

**Motivo:** O template anterior era uma estrutura mínima herdada do OpenCart com variáveis legadas (`column_left`, `column_right`, `content_top`, `content_bottom`) e sem nenhum estilo próprio, tornando a página visualmente inconsistente com a Alpha Engine.

**Benefício:** A página de pedidos agora é premium e consistente com o design da Alpha Engine — feedback visual claro de status, navegação intuitiva e resposta a qualquer estado do pedido.
