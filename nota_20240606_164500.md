# Implementação: Sistema Global de Notificações (Toasts)

**Implementação**: Criação de um método `window.showNotification(message, type)` injetado no escopo global através do arquivo `app.js`. O sistema cria um container fixo (`#egen-toast-container`) dinamicamente no DOM e injeta balões de notificação usando as classes base de alerta já existentes (`.egen-alert`).

**Motivo**: A loja precisava de uma forma padronizada, moderna e visualmente atraente para dar feedback aos usuários durante interações assíncronas (como Adicionar ao Carrinho, Adicionar à Lista de Desejos, Erros de Login via AJAX), substituindo funções obstrutivas bloqueantes como o `alert()` nativo do JavaScript.

**Benefício**: Centralização do comportamento de *feedback* da interface, tornando o código reutilizável para qualquer integração de API e proporcionando uma experiência de usuário (UX) com aspecto Premium, com suporte a animações *slide-in* fluidas e auto-descarte sem exigir marcações fantasmas permanentes no arquivo HTML base.

## Questão
Devemos adicionar um sistema global de alertas ou notificações em `app.js` para mostrar feedbacks de sucesso e erro ao usuário?

## Resposta Completa do Assistente
Sem dúvida! Essa é uma evolução arquitetural fundamental para a experiência do usuário (UX). Ter um sistema de notificações globais (*Toasts* ou *Snackbars*) não intrusivo e centralizado evita o uso dos feios `alert()` nativos do navegador e garante que toda a equipe (ou qualquer outro script de carrinho, login e wishlist) possua uma forma padronizada de se comunicar com o cliente.

Como já possuímos os seletores visuais `.egen-alert`, `.egen-alert--success` e `.egen-alert--danger` desenhados no seu arquivo `new-stylesheet.css`, a abordagem mais limpa é construir no `app.js` uma função acessível globalmente (`window.showNotification`) que gere esse componente de forma dinâmica no DOM. Adicionei até mesmo as animações nativas de transição!
