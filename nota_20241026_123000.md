# Refatoração: Script de Substituição Automática de Idiomas

**Implementação**: Criação de um script Bash (`refactor_load_language.sh`) injetado com expressões regulares em Perl para realizar a substituição condicional da chamada de linguagem legada (`$this->load->language`) para a nova infraestrutura Alpha Engine (`$this->loadLanguageData`).

**Motivo**: Após auditoria constatando centenas de resquícios de chamadas legadas nos Controladores, a refatoração manual arquivo por arquivo tornou-se insustentável. No entanto, um simples *Find and Replace* global quebraria o código, pois a nova estrutura injeta um array `$data` que não é necessário (nem declarado) em métodos que funcionam como endpoints JSON (`save`, `confirm`, `delete`).

**Benefício**: Automatização segura do débito técnico. O script age como um mini-analisador léxico: rastreia em qual método está atuando e aplica a substituição apenas em rotas conhecidas de visualização de tela (`index`, `info`, `form`, etc.), ganhando horas de desenvolvimento seguro.

## Questão
Achei vários métodos! Você pode criar um script Bash parecido com aquele `find_unused_models.sh` que substitui automaticamente o `$this->load->language` nesses arquivos de View?

## Resposta Completa do Assistente
Com certeza! Como você pontuou muito bem, fazer uma substituição "cega" (um *Find & Replace* simples) pode quebrar os métodos de API/JSON (como `save()`, `confirm()` e `delete()`), já que eles não precisam da injeção no array `$data`.

Para resolver isso de forma elegante, criei um script Bash (`refactor_load_language.sh`). Por baixo dos panos, ele usa a engine do **Perl** (nativa no Debian) para agir como um "mini-analisador léxico". Ele lê o arquivo linha por linha, memoriza o nome do método em que está atualmente e, caso encontre o `load->language`, ele só faz a substituição se o método for de visualização (ex: `index`, `add`, `info`, `form`, `list`, etc.).
