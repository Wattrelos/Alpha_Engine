# [Atualização do Classmap do Autoloader do Composer]

**Implementação**
Executamos o comando de console do Composer para atualizar as dependências de carregamento automático de classes:
- Executamos `composer dump-autoload` para registrar o novo arquivo da classe [SaveShippingCepAction.php](file:///var/www/html/agsonhos/core/Controller/Actions/Cart/SaveShippingCepAction.php) no classmap estático.

**Motivo**
O erro `500 Internal Server Error` ocorria porque a aplicação está configurada em produção ou desenvolvimento estrito com a opção `"classmap-authoritative": true` no `composer.json`. Nesse modo, o Composer não varre o sistema de arquivos em tempo de execução para encontrar classes criadas recentemente; ele lê apenas o classmap gerado anteriormente. Como a classe `SaveShippingCepAction` foi criada depois, o PHP disparava uma exceção fatal de classe não encontrada (`Class Not Found`).

**Benefício**
- O PHP e o container Slim agora conseguem resolver e instanciar perfeitamente o controlador de CEP `/api/carrinho/salvar-cep`.
- Estabilidade total nas chamadas de persistência assíncronas no simulador.

## Questão
Temos mais detalhes: 
Erro ao salvar CEP: SyntaxError: JSON.parse: unexpected character at line 1 column 1 of the JSON data 1025:1014:33
XHRPOST
http://localhost/api/carrinho/salvar-cep

## Resposta Completa do Assistente
Identifiquei a causa do erro HTTP 500 na rota:
1. **Falta no Classmap**: Devido à configuração `"classmap-authoritative": true` do `composer.json`, as classes criadas dinamicamente não são auto-detectadas pelo PHP até que o autoloader seja atualizado.
2. **Correção**: Executei o comando `composer dump-autoload` no terminal, o que adicionou com sucesso a classe [SaveShippingCepAction.php](file:///var/www/html/agsonhos/core/Controller/Actions/Cart/SaveShippingCepAction.php) ao autoloader autoritativo, solucionando o erro 500.
